# Data model

The Postgres schema, its constraints, and the ordering/identity conventions. App tables live in
`server/database/schema/`; Better Auth tables are generated by `@better-auth/cli` and committed alongside.
**drizzle-kit owns all migrations.**

## Conventions

- **IDs** — app tables use **uuidv7** primary keys (`uuidv7` package). uuidv7 is time-sortable, so it doubles
  as the ordering tiebreaker. Better Auth ids stay `text` (its own format).
- **Ordering** — a `position text` column holds a **fractional index** (`fractional-indexing-jittered`).
  Insert/move computes `generateKeyBetween(prev, next)`; jitter prevents identical colliding keys under
  concurrent same-slot inserts. **Always sort `(position, id)`.**
- **Validation** — `drizzle-zod` (0.8, Zod-4-aware) derives insert/select schemas for **app tables only**. The
  API contract in `shared/schemas/` composes these. A smoke test parses a sample row through a generated schema
  so a future zod/drizzle-zod bump fails in CI.
- **Timestamps** — `createdAt` / `updatedAt` (`timestamptz`) on every app table.
- **Scoping** — every app row carries `userId`; every query filters by it.

## Tables

### Better Auth (generated, committed)
`user` (+ `role`, `banned`, `banReason`, `banExpires` from the admin plugin), `session`, `account`,
`verification`. Do not hand-edit; re-run `pnpm auth:gen` after auth config changes, then `pnpm db:generate`.

### `task` — the core
| Column | Type | Notes |
|---|---|---|
| `id` | uuidv7 PK | |
| `userId` | → user | |
| `date` | date? | day-column bucket |
| `listId` | uuidv7? → list | list bucket |
| `position` | text | fractional index within the bucket |
| `title` | text | |
| `note` | text? | italic annotation |
| `highlightColor` | enum? | `persimmon` \| `amber` \| `jade` \| `indigo` \| `magenta` (the highlighter ink) |
| `timeOfDay` | time? | display label only (◷) — **no** hourly scheduling |
| `completedAt` | timestamptz? | null = open; timestamp enables stats |
| `originalDate` | date? | kept when a rollover moves the task ("rolled" ⇔ `originalDate < date`) |
| `recurrenceRule` | text? | reserved; materialization deferred (see [roadmap](./roadmap.md)) |
| `sourceEventId` | uuidv7? → calendar_event | set when created from / kept-linked to an imported event |
| `sourceLabel` | text? | cached provider label for the "⤺ from …" pill |

**Bucket invariant** — a task is on a day **or** in a list, never both, never neither:
`CHECK (num_nonnulls(date, list_id) = 1)`.
**Indexes** — `(userId, date)`, `(userId, listId)`, `(userId, completedAt)`.

### `subtask` — schema-ready (UI deferred, see [decisions.md](./decisions.md))
`id` uuidv7 PK · `taskId` → task (**ON DELETE CASCADE**) · `title` · `position` (fractional) · `completedAt?`.

### `calendar_source` — a calendar within a connection
`id` · `connectionId` → connection (**CASCADE**) · `remoteId` · `name` · `color` · `enabled` bool ·
incremental cursors: `syncToken?` (Google) / `ctag?`+`etag?` (CalDAV) / `httpEtag?`+`lastModified?` (iCal) ·
`lastSyncedAt?`.

### `calendar_event` — read-only mirror (cache)
| Column | Type | Notes |
|---|---|---|
| `id` | uuidv7 PK | |
| `userId` | → user | indexed with `localDate` |
| `sourceId` | → calendar_source | **CASCADE** |
| `remoteUid` | text | provider UID (+ RECURRENCE-ID for instances) |
| `title` | text | |
| `startAt` · `endAt` | timestamptz | |
| `allDay` | boolean | |
| `localDate` | date | the date it lands on in the user's tz (grid queries hit this) |
| `timeLabel` | text? | precomputed "14:30" |
| `status` | enum | `confirmed` \| `cancelled` (cancelled hidden) |

**Dedupe** — `UNIQUE (sourceId, remoteUid, startAt)` collapses recurring instances.
**Index** — `(userId, localDate)`.

## Rollover mechanics

When `rolloverEnabled`, open tasks with `date < today` move to today: set `date = today`, keep `originalDate`
(first move only), re-`position` at the end of today. The **authoritative** path is a **lazy, idempotent**
server pass when a week containing today is loaded; a daily Nitro task (per-user `timezone`) is a belt-and-
braces backstop. Events never roll over.

## Entity sketch

```
user ─1:1─ user_settings
user ─1:*─ list ─1:*─ task ─1:*─ subtask
user ─1:*─ task            (date-bucketed tasks have no list)
user ─1:*─ calendar_connection ─1:*─ calendar_source ─1:*─ calendar_event
task.sourceEventId ─?─▶ calendar_event   (kept-linked convert)
```

See [architecture.md](./architecture.md) for how these are queried and [calendar-sync.md](./calendar-sync.md)
for how `calendar_event` is populated.
